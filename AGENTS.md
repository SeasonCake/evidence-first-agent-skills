# Contributor guidance

- Keep every skill usable without private chats, project paths, credentials, or hidden inputs.
- Skills advise or verify; they do not create deployment, publication, or destructive authority.
- Each skill must keep its own attribution file and pass `python scripts/verify.py`.
- Use synthetic examples when adding tests or references.
- Lead public pages with practical value, architecture, examples, and contribution
  routes. Keep internal review/privacy/provenance details in the relevant documentation
  rather than duplicating them as a standalone promotional-page section.
- Keep `LICENSE`, README files, project-origin notes, attribution, and companion links
  consistent when public project identity changes.
