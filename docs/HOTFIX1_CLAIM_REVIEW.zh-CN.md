# 从日志到可靠结论：8个可运行的证据审查案例

[English](HOTFIX1_CLAIM_REVIEW.md) · [合成回执示例](../examples/claim_receipts.py)

从 BidKing `0.3.4-hotfix1` 维护及后续工程回顾中提炼，用8个合成回执演示怎样缩小结论范围、
定位仪器误判，并给出下一步可执行的检查。可以与现有四个skills配合使用。

## 1. 一个容易出错的推断

设用户亲眼看到了流程第五步，但导出的文件中没有对应事件。能够确认的是：
“在这个导出中没有找到目标事件”。不能跳到“用户没有到第五步”，也不能推断用户现在仍处于第五步。

先分清三层覆盖面：

1. 搜索是否完整执行、查询语义是否受支持；
2. 文件是否完整代表目标session/版本/时段，以及导出是否保留瞬时事件；
3. 用户一手观察和搜索对象是否在回答同一个问题。

第一层完整不能自动补齐第二层。作者的时序说明要保留为独立证据；搜索未命中不是推翻它的理由。
真实事件为什么未被保留，需要另外的可证伪检查，不能由零计数补出唯一根因。

## 2. 可执行的局部结论合同

运行标准库示例：

```powershell
python examples/claim_receipts.py
python -m unittest discover -s tests -p test_claim_receipts.py -v
```

脚本读取同目录的合成JSON并逐项验证结果，运行后即可看到每类回执支持的结论。

| 合成输入 | 可报告结果 | 不能报告 |
| --- | --- | --- |
| 完整搜索、命中 | 选定范围中观察到 | 所有版本/用户都有该行为 |
| 完整搜索、未命中 | 选定范围中未观察到 | 现实事件从未发生 |
| 部分、超时、拒绝、读取错误 | 不确定 | 未命中证明不存在 |
| 按行引擎收到跨行查询 | 查询不支持 | 字符串在文件中不存在 |
| 某个gate已measured | 该gate已具测量成熟度 | 整个产品已发布或可发布 |
| 某个gate仅implemented | 该gate尚未measured | 任意当前版本必须阻断 |

`absence_supported` 只指受支持查询在所声明选定范围内的未命中结论；它不是导出完整性的证明。
`proves_event_never_happened` 始终为false。计数为布尔值、状态与完成性矛盾等输入会报错，不返回假阴性。
这是回执解释示范，不能验证回执是否真实；真实工具仍须有known-good、known-fail和具体范围证据。

## 3. 更好的纠偏回投

用一段话给出“事实 → 影响 → 未知 → 最小下一步”，例如：

> 已完整搜索本次提供的文件，未见目标事件；另有独立记录说明流程到过第五步。因此这份导出不能
> 证明该事件标识，但不能否认流程第五步发生。尚未查明事件保留规则；下一步只核同版本导出路径，
> 不要求用户重跑整个流程。

如果后来出现新证据，明确哪条旧结论被取代。不要把工具自身中断、窗口重连或读取失败投射到用户
操作和样本来源。也不要为了“验收更严格”把未适用的新工具成熟度门加入已经完成的产品发布。

## 4. 资源也是实验条件

先用具名文件和已知项目索引，定义文件数/字节/时限/输出预算；管道只取前几行不能限制上游遍历。
卡顿或取消后确认自有进程退出，不按名称杀掉全机同名进程。本示例不实施系统级拦截或后台监控。
